## English

- **Plugin code now executes only after metadata validation and inside a bounded worker (#4598)** — cdidx checks the plugin marker and API range without loading the DLL, then isolates assembly loading, construction, and symbol/reference extraction behind wall-clock, working-set, and protocol-output limits. Load failures are cached by content fingerprint, so explicit project/status refresh checkpoints retry repaired partial copies while hot-path lookups do not restage unchanged DLLs.

## 日本語

- **plugin codeはmetadata検証後にbounded worker内だけで実行するようになりました (#4598)** — cdidxはDLLをloadせずにplugin markerとAPI rangeを検証し、assembly load、construction、symbol / reference extractionをwall-clock、working-set、protocol-output上限の内側へ隔離します。load失敗はcontent fingerprint単位でcacheするため、明示的なproject / status refresh checkpointで修復したpartial copyを再試行し、hot-path lookupでは変更のないDLLを再stagingしません。

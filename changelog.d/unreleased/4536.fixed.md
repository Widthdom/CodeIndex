## English

- **Configured MCP request concurrency is now effective and bounded for stdio and HTTP (#4536)** — independent requests execute up to the server limit, including base transports at `maxConcurrency: 1` without double-acquiring the execution gate; the accepted backlog rejects overflow with retry-safe `server_busy`, queued request ids remain cancellable, timeouts retain their lease until live actions drain, session mutations preserve receive order, and request-scoped HTTP writers keep every response attached to its originating POST.

## 日本語

- **設定した MCP request concurrency が stdio と HTTP で bounded に機能するようになりました (#4536)** — base transport でも `maxConcurrency: 1` で execution gate を二重取得せず、独立 request は server 上限まで実行されます。accepted backlog 超過は retry-safe な `server_busy` で拒否し、queued request id は cancellation 可能なまま維持します。timeout 後も live action が drain するまで lease を保持し、session mutation の受信順と request-scoped HTTP response binding を保ちます。

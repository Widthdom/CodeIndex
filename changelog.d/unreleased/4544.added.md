## English

- **MCP `resources/read` now supports bounded ranges and continuation (#4544)** — callers can select inclusive line ranges and a UTF-8 byte budget, while bounded defaults, explicit truncation metadata, and version-bound cursors keep large single-line and multi-line resources from being fully materialized before pagination. Pages are also limited to 1,000 logical lines, adapt to tighter enclosing MCP/HTTP response limits, share the aggregate frame ceiling across JSON-RPC batch items (preserving IDs with compact structured errors when an item cannot fit), and use one SQLite read snapshot. Read-only or immutable legacy databases without the new partial indexes use a metadata-only, VM-step-budgeted `idx_chunks_file` fallback; budget exhaustion and incomplete or unsafe indexed storage return structured errors instead of partial success or unbounded scans.

## 日本語

- **MCP `resources/read` が上限付き range と continuation に対応しました (#4544)** — inclusive な行範囲と UTF-8 byte budget を指定でき、上限付きの既定値、明示的な truncation metadata、resource 版に結び付いた cursor により、長い単一行・複数行 resource を pagination 前に全文 materialize しなくなりました。ページは論理行 1,000 行でも制限され、より小さい MCP / HTTP レスポンス上限に適応し、JSON-RPC batch item 間で aggregate frame 上限を共有し（item が収まらない場合も compact な構造化 error で ID を保持）、単一の SQLite read snapshot を使用します。新しい partial index がない read-only または immutable な legacy database では、metadata-only かつ VM-step budget 付きの `idx_chunks_file` fallback を使います。budget 超過や不完全または安全上限を超える index storage は部分成功や無制限 scan ではなく構造化 error を返します。

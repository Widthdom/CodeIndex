## English

- **Bounded HTTP MCP request lifetimes and propagated disconnect cancellation (#4546)** — Configurable body-idle and total deadlines now cover request reading, queueing, tool/SQLite execution, and response completion. Established-session response-bearing JSON-RPC requests use serialized, bounded chunked-whitespace probes to detect clients that disconnect after upload, while the initial headerless `initialize` and notifications skip probing so session headers and `204 No Content` semantics are preserved. Probe failure, timeout, disconnect, and shutdown paths cancel active work; cancellation-ignoring work keeps its bounded concurrency and body-budget leases until it actually exits, and output-stream ownership is not handed to a later response while an earlier write is still settling. Non-cooperative response, probe, and SSE output operations share a bounded registry, and probe request-body leases remain held until their underlying output settles.

## 日本語

- **HTTP MCP request lifetime を制限し切断 cancellation を伝播 (#4546)** — 設定可能な body-idle deadline と total deadline が、request read、queue、tool / SQLite 実行、response 完了までを制限するようになりました。session 確立後の応答を伴う JSON-RPC request は、直列化され bounded な chunked whitespace probe により upload 後の client 切断を検出し、最初の headerless `initialize` と notification は probe を行わず session header と `204 No Content` の意味を維持します。probe failure、timeout、disconnect、shutdown の各経路は実行中の work を cancel します。cancellation を無視する work も実際に終了するまでは bounded concurrency と body-budget の lease を保持し、先行 write の終了処理中に同じ output stream の所有権を後続 response へ渡しません。非協調的な response、probe、SSE の output operation は共通の bounded registry で管理し、probe の request-body lease は基礎 output が完了するまで保持します。

## English

- **Warn when the worktree HEAD has switched since the index was built (#1512)** — `index` now records the git HEAD commit alongside the indexed project root (new `indexed_git_head` meta key), and `status` (CLI text and JSON) compares the persisted HEAD against the runtime HEAD for the worktree. When they diverge — for example after `git worktree add` or `git switch` inside a worktree — `status` surfaces the new `indexed_git_head` / `worktree_head_changed` fields and the text mode prints a `WARN` line with a ready-to-run reindex command. MCP `repo/status` and related responses carry the same fields so automation can detect a stale worktree before issuing further queries. Legacy DBs without the persisted HEAD return null fields and trigger no warning, preserving back-compat.

## 日本語

- **worktree の HEAD が index 構築後に切り替わった場合に警告 (#1512)** — `index` は indexed_project_root と合わせて git HEAD コミットを保存するようになり (`indexed_git_head` メタキーを追加)、`status` (CLI テキストおよび JSON) で persisted HEAD と現在の worktree の HEAD を突き合わせます。`git worktree add` や worktree 内で `git switch` した直後など差分がある場合は、`status` に新フィールド `indexed_git_head` / `worktree_head_changed` を表示し、テキストモードでは再 index 用コマンドを含む `WARN` 行を出力します。MCP の `repo/status` ほか同種レスポンスにも同じフィールドを載せたため、オートメーション側が古い worktree を後続クエリ前に検知できます。persisted HEAD を持たない旧 DB ではフィールドは null となり警告も出ないので、後方互換を維持します。

## English

- **Failed MCP initialization no longer poisons session identity or capabilities (#4540)** — cdidx now stages client identity, caller, roots, and capabilities until protocol negotiation and successful response serialization complete, so an unsupported handshake, `CDIDX_MCP_RESPONSE_MAX_BYTES` fallback, or serializer failure cannot affect audit attribution, rate-limit identity, root authorization, or a corrected retry. A successful initialize publishes lifecycle and all negotiated metadata together through one immutable snapshot; concurrent or draining requests see one complete generation, and an older in-flight `roots/list` response cannot overwrite a newer handshake. HTTP delivery uses a separate fail-closed boundary documented with the HTTP transport.

## 日本語

- **失敗した MCP initialize が session identity や capabilities を汚染しなくなりました (#4540)** — cdidx は protocol 交渉と成功 response の serialization が完了するまで client identity、caller、roots、capabilities を一時状態に保持するため、未対応 handshake、`CDIDX_MCP_RESPONSE_MAX_BYTES` fallback、serializer failure が audit attribution、rate-limit identity、root authorization、または修正後の再試行へ影響しません。成功した initialize は lifecycle とすべての交渉済み metadata を単一の immutable snapshot として同時に公開するため、並行中または drain 中の request は完全な 1 世代だけを参照し、古い進行中の `roots/list` response が新しい handshake を上書きすることもありません。HTTP 配送には HTTP transport とともに文書化した別の fail-closed 境界があります。

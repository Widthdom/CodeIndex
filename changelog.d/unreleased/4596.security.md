## English

- **Plugin and hook DLLs now cross one secure filesystem boundary before execution (#4596)** — Default and overridden extension directories validate ownership, effective writable permissions, every ancestor, containment, and regular-file leaves while ignoring Windows inherit-only ACEs that do not apply to the inspected component. Accepted bytes are hashed into private read-only staging before assembly load, preventing unsafe-directory and validation-to-load rename swaps. Windows CI places its protected current-user temp root under `USERPROFILE`, so extension fixtures exercise the same boundary without inheriting shared `RUNNER_TEMP` ancestry.

## 日本語

- **plugin / hook DLL は実行前に単一の安全な filesystem boundary を通過するようになりました (#4596)** — 既定および override の extension directory で owner、実効 writable permission、全祖先、containment、regular-file leaf を検証し、検査対象 component 自身には適用されない Windows の inherit-only ACE は除外します。受理した bytes は assembly load 前に private read-only staging へ hash 付きで固定し、unsafe directory と validation-to-load 間の rename swap を防ぎます。Windows CI の current-user 限定 protected temp root は `USERPROFILE` 配下に置き、shared `RUNNER_TEMP` 祖先を継承せず同じ boundary を extension fixture で検証します。

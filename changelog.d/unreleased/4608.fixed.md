## English

- **Made C-versus-C++ `.h` detection lexical and budget-aware (#4608)** — header scoring now reuses a stateful C/C++ comment and string masker, ignores continued preprocessor payloads, and replaces the first-200-lines cutoff with a 48 KiB UTF-8 scoring budget over full-header or head/middle/tail ranges. Lexical state streams across skipped bytes, translation-phase line splices can form comment and raw-string delimiters, and partial-token sample starts cannot invent line-start markers. Ambiguous decisions expose stable source/confidence metadata through dry-run output, and comment-only or macro-string C++ words no longer promote C headers.

## 日本語

- **`.h` の C/C++ 判定を字句解析ベースかつ budget-aware にしました (#4608)** — ヘッダー評価で状態を保持する C/C++ コメント・文字列マスカーを再利用し、継続するプリプロセッサのペイロードを無視します。先頭200行の打ち切りは、ヘッダー全体または先頭・中央・末尾 range を対象にした48 KiB の UTF-8 scoring budget へ置き換えました。評価対象外の byte をまたいで字句状態を追跡し、translation-phase の行 splice で形成されるコメント・raw string delimiter を認識します。token 途中から始まる sample が行頭 marker を作り出すこともありません。曖昧な判定の安定した判定元・信頼度 metadata を dry-run 出力で公開し、コメントだけ、またはマクロ文字列だけにある C++ 語彙で C ヘッダーが昇格しなくなりました。

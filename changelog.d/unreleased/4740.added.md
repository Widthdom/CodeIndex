## English

- **Repository metadata formats now provide structured symbol, reference, and graph capabilities (#4740)** — TOML, JSON Lines/NDJSON, Git and Docker ignore files, Git attributes, EditorConfig, and `.rules` files expose conservative sections, keys, rules, and repository-local path edges. Windows application manifests now expose dependent assembly and local file/path references, with unsafe path forms suppressed. Bounded extraction remains persistable for large inputs, including EditorConfig character classes and TOML-escaped Windows paths.

## 日本語

- **repository metadata 形式で構造化 symbol / reference / graph 機能を利用できるようにしました (#4740)** — TOML、JSON Lines / NDJSON、Git / Docker ignore file、Git attributes、EditorConfig、`.rules` file が、保守的な section、key、rule、repository-local path edge を出力します。Windows application manifest も依存 assembly と local file / path reference を出力し、安全でない path 形式は抑止します。大規模入力でも bounded extraction が永続化可能な結果を保ち、EditorConfig の character class と TOML で escape された Windows path にも対応します。

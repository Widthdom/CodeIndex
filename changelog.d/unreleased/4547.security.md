## English

- **Hardened MCP rate limiting before tool-call validation (#4547)** — Every direct `tools/call` now consumes a caller-wide coarse quota before detailed validation, canonical known tools retain secondary per-tool limits, and unrecognized names cannot create name-derived buckets. Unknown `batch_query` slot names share one bounded key, while layered bucket-cap responses include both charged-token refill and capacity recovery in the advertised delay, preventing cross-tool malformed-call bypass, cardinality exhaustion, retry churn, or prolonged legitimate-client starvation.

## 日本語

- **MCP の tool-call 検証前レート制限を強化しました (#4547)** — direct な `tools/call` request はすべて詳細検証前に caller-wide coarse quota を消費し、canonical な既知 tool は secondary per-tool 制限を維持し、未認識名は名前由来 bucket を作成しません。unknown な `batch_query` slot 名は 1 つの bounded key を共有し、layered bucket-cap 応答は消費済み token の refill と capacity 回復の両方を通知時間へ含めるため、既知名ローテーションによる malformed-call bypass、cardinality 枯渇、retry churn、正規 client の長時間拒否を防ぎます。

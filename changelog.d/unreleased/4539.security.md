## English

- **HTTP MCP clients can no longer share mutable session state (#4539)** — each server process now issues a standard `Mcp-Session-Id` after successful initialization and requires it on every later POST and event stream, preventing another client from changing the established caller, roots, or capabilities. If `CDIDX_MCP_HTTP_MAX_RESPONSE_BYTES` rejects an already serialized initialize response, HTTP 500 still carries the new session ID and the transport retains the committed session fail-closed.

## 日本語

- **HTTP MCP client 間で可変 session state が共有されなくなりました (#4539)** — server process ごとに initialize 成功後、標準 `Mcp-Session-Id` を発行し、以後のすべての POST と event stream で同じ値を要求するため、別 client が確立済み caller、roots、capabilities を変更できません。すでに serialization 済みの initialize response を `CDIDX_MCP_HTTP_MAX_RESPONSE_BYTES` が拒否する場合も、HTTP 500 は新しい session ID を返し、transport は committed session を fail-closed で保持します。

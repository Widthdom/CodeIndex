## English

- **Installer execution now requires independent release provenance by default (#4603)** — `install.sh` fails closed unless the checksum manifest has a GitHub attestation pinned to the CodeIndex release workflow and selected tag or a signature from a pinned GPG signer, while `cdidx upgrade` verifies both the manifest and installer script before trusting checksums or launching code. The former permissive behavior remains only through an explicit audited `CDIDX_VERIFY_POLICY=compat` opt-in. Upgrade JSON distinguishes strict verification failures from compat bypasses, emits the compat audit code only for the latter, and preserves structured usage errors for invalid policy values.

## 日本語

- **installer 実行時に独立した release provenance を既定で必須にしました (#4603)** — `install.sh` は checksum manifest に CodeIndex release workflow と選択 tag に固定した GitHub attestation、または fingerprint 固定済み GPG signer の署名が無ければ fail closed し、`cdidx upgrade` は checksum を信頼したり code を起動したりする前に manifest と installer script の両方を検証します。従来の許容的な動作は、監査対象となる `CDIDX_VERIFY_POLICY=compat` の明示的 opt-in でのみ利用できます。upgrade JSON は strict verification failure と compat bypass を区別し、後者にだけ compat audit code を出力し、無効な policy 値でも構造化 usage error を維持します。

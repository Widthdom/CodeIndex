## English

- **Read-only recovery no longer hides broad SQLite I/O failures or hot WAL state (#4555)** — Automatic recovery excludes generic `SQLITE_IOERR`, requires compatible `CANTOPEN` and filesystem evidence, and retries only with WAL-aware read-only mode. `immutable=1` now requires explicit caller opt-in and every affected JSON response marks the resulting stale-snapshot risk.

## 日本語

- **Read-only recovery が広範な SQLite I/O failure や hot WAL state を隠さなくなりました (#4555)** — 自動 recovery は汎用 `SQLITE_IOERR` を除外し、compatible な `CANTOPEN` と filesystem evidence を要求したうえで WAL-aware な read-only mode だけを再試行します。`immutable=1` は caller の明示 opt-in が必須となり、影響を受けるすべての JSON response が stale-snapshot risk を示します。
